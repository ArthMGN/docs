## Visão Geral

A API de Estoque Geral do WMS foi desenvolvida para permitir que **sistemas externos** consultem a posição atual de estoque da empresa autenticada de forma padronizada e segura.

A consulta permite visualizar o estoque em diferentes níveis de consolidação, possibilitando integrações com ERPs, portais, sistemas legados e outras aplicações externas.

É possível filtrar a consulta por:

- código do produto;
- lote;
- endereço;
- etiqueta.

Além dos filtros, o integrador pode definir como as informações serão agrupadas.

Os agrupamentos disponíveis são:

- `produto`;
- `produto_lote`;
- `endereco`;
- `etiqueta`.

Quando `agrupar_por` não for informado, o WMS utiliza automaticamente:

```text
produto_lote
```

A consulta sempre é limitada à **empresa associada ao usuário autenticado**.

Método HTTP: `POST /v1/consultar-estoque`

## Headers

| Nome | Valor |
| :-- | :-- |
| Content-Type | `application/json` |
| Authorization | `Bearer <token>` |

## Campos

Todos os filtros são opcionais.

| Nome | Tipo | Obrigatório | Descrição |
| :-- | :-- | :-: | :-- |
| `produto_codigo` | string | Não | Código do produto |
| `lote` | string | Não | Lote do produto |
| `endereco_codigo` | string | Não | Código do endereço. Exemplo: `A-01-B-001` |
| `etiqueta_codigo` | string | Não | Código da etiqueta |
| `agrupar_por` | string | Não | Forma de agrupamento. Valores aceitos: `produto`, `produto_lote`, `endereco` ou `etiqueta` |

Os filtros podem ser combinados.

Exemplo:

```json
{
  "produto_codigo": "AGUA001",
  "lote": "AGA0919",
  "endereco_codigo": "A-01-B-001",
  "agrupar_por": "produto_lote"
}
```

## Normalização dos Filtros

Os campos abaixo são normalizados para letras maiúsculas antes da consulta:

```text
produto_codigo
endereco_codigo
etiqueta_codigo
```

O campo `agrupar_por` é normalizado para letras minúsculas.

O campo `lote` é utilizado conforme informado após a remoção de espaços no início e no final.

## Registros considerados na consulta

A API retorna somente registros de estoque que possuam:

```text
quantidade_disponivel > 0
```

Além disso, registros de estoque com os seguintes `status_id` não são considerados:

```text
0
5
```

<Note>
  A consulta considera a quantidade disponível registrada no estoque. Registros sem quantidade disponível positiva não são retornados, mesmo que possuam quantidade reservada ou bloqueada.
</Note>

## Quantidades

Dependendo do agrupamento utilizado, a resposta poderá apresentar:

| Campo | Descrição |
| :-- | :-- |
| `quantidade_disponivel` | Quantidade disponível registrada no estoque |
| `quantidade_reservada` | Quantidade atualmente reservada |
| `quantidade_bloqueada` | Quantidade atualmente bloqueada |
| `quantidade_total` | Soma das quantidades disponível, reservada e bloqueada |

O cálculo de `quantidade_total` é:

```text
quantidade_disponivel
+ quantidade_reservada
+ quantidade_bloqueada
```

<Note>
  `quantidade_total` representa a soma física registrada na posição consultada. Ela não deve ser interpretada como quantidade livre para novas reservas.
</Note>

## Agrupamentos

### produto

Agrupa todos os registros de estoque por produto.

Exemplo de requisição:

<RequestExample>

```json body
{
  "produto_codigo": "AGUA001",
  "agrupar_por": "produto"
}
```

</RequestExample>

O retorno por produto contém:

| Campo | Descrição |
| :-- | :-- |
| `produto_id` | Identificador interno do produto |
| `produto_codigo` | Código do produto |
| `produto_descricao` | Descrição do produto |
| `unidade_medida` | Unidade de medida cadastrada |
| `total_linhas` | Quantidade de registros de estoque considerados |
| `total_enderecos` | Quantidade de endereços distintos |
| `total_etiquetas` | Quantidade de etiquetas distintas |
| `quantidade_disponivel` | Soma da quantidade disponível |
| `quantidade_reservada` | Soma da quantidade reservada |
| `quantidade_bloqueada` | Soma da quantidade bloqueada |
| `quantidade_total` | Soma total das quantidades |
| `peso_bruto_total` | Peso bruto total |
| `peso_liquido_total` | Peso líquido total |
| `validade_min` | Menor data de validade encontrada |
| `validade_max` | Maior data de validade encontrada |

### produto_lote

Agrupa o estoque por:

```text
produto + lote + data de validade
```

Este é o agrupamento padrão da API.

Exemplo:

<RequestExample>

```json body

}
```

</RequestExample>

| `produto_descricao` | Descrição do produto |

| `total_linhas` | Quantidade de registros de estoque |

| `peso_liquido_total` | Peso líquido total |

## Consulta sem filtros

Todos os filtros são opcionais.

Uma requisição sem filtros pode ser enviada como:

<RequestExample>

```json body
{}
```

</RequestExample>

Nesse caso, o WMS utiliza automaticamente:

```text
agrupar_por = produto_lote
```

e retorna o estoque da empresa autenticada agrupado por produto, lote e data de validade.

## Combinação de filtros

Os filtros podem ser utilizados em conjunto.

Exemplo:

```json
{
  "produto_codigo": "PROD001",
  "lote": "LT20260001",
  "endereco_codigo": "A-01-B-001",
  "agrupar_por": "etiqueta"
}
```

Nesse cenário, somente registros que atendam a **todos os filtros informados** serão considerados.

## Retorno sem estoque

Quando nenhum registro de estoque atender aos filtros informados, a requisição continua sendo considerada válida.

Exemplo:

<ResponseExample>

```json 200
{
  "ok": true,
  "status": 200,
  "message": "Consulta de estoque realizada com sucesso",
  "data": {
    "filtros": {
      "produto_codigo": "PROD-INEXISTENTE",
      "lote": null,
      "endereco_codigo": null,
      "etiqueta_codigo": null,
      "agrupar_por": "produto_lote"
    },
    "resultado": []
  }
}
```

</ResponseExample>

A ausência de estoque não é tratada como erro da integração.

## Erros comuns

| Código | Mensagem | Causa Provável |
| :-- | :-- | :-- |
| 400 | `p_agrupar_por inválido. Valores aceitos: produto, produto_lote, endereco, etiqueta` | O valor informado em `agrupar_por` não corresponde a um dos agrupamentos disponíveis |
| 401 | `Sessão inválida` | Token Bearer ausente, inválido, expirado ou não reconhecido |
| 401 | `Não foi possível determinar a empresa` | O usuário autenticado não está corretamente associado a uma empresa |
| 500 | Erro interno ao consultar estoque | Falha inesperada durante o processamento da consulta ou acesso às informações de estoque |

## Observações sobre os agrupamentos

Os campos retornados variam de acordo com o valor de `agrupar_por`.

Por exemplo:

```text
produto
→ consolida todas as posições do produto

produto_lote
→ consolida por produto + lote + validade

endereco
→ consolida todo o estoque existente no endereço

etiqueta
→ retorna as posições de estoque individualizadas por etiqueta
```

Por esse motivo, sistemas integradores devem interpretar a estrutura de `resultado` conforme o agrupamento solicitado.

<Note>
  - Se `agrupar_por` não for informado, será utilizado automaticamente `produto_lote`.
  - Todos os filtros são opcionais e podem ser combinados.
  - A consulta é restrita à empresa vinculada ao usuário autenticado.
  - Somente registros com `quantidade_disponivel` maior que zero são retornados.
  - Registros com `status_id` igual a `0` ou `5` não são considerados.
  - `quantidade_total` corresponde à soma de `quantidade_disponivel`, `quantidade_reservada` e `quantidade_bloqueada`.
  - O agrupamento `etiqueta` apresenta o maior nível de detalhamento disponível nesta consulta.
  - A API é exclusivamente de consulta e não realiza reserva, bloqueio ou movimentação de estoque.
</Note>
